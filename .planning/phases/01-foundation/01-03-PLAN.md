**Créer src/lib/auth.ts** (configuration centrale de Better Auth) :

```typescript
/**
 * Configuration Better Auth — authentification de l'artiste.
 *
 * Better Auth gère :
 * - La création et vérification des sessions (cookies httpOnly signés)
 * - Le hashage sécurisé des mots de passe (bcrypt intégré)
 * - Ses propres tables en base (user, session, account) via le Drizzle adapter
 *
 * POURQUOI Better Auth et pas NextAuth ?
 * Better Auth est plus simple pour un usage email+mot de passe seul,
 * et son adapter Drizzle s'intègre directement avec notre pool PostgreSQL
 * existant — pas besoin d'une connexion séparée.
 *
 * [D-05] : email + mot de passe uniquement, pas de magic link ni OAuth
 */

import { betterAuth } from 'better-auth'
import { drizzleAdapter } from 'better-auth/adapters/drizzle'
import { db } from '@/db'

export const auth = betterAuth({
  // Connexion à PostgreSQL via le pool Drizzle existant
  // Better Auth crée et gère ses propres tables (user, session, account)
  database: drizzleAdapter(db, {
    provider: 'pg', // Indique que c'est PostgreSQL (pas MySQL ni SQLite)
  }),

  // Activation de l'authentification par email + mot de passe [D-05]
  // Les magic links et OAuth sont désactivés — usage personnel simple
  emailAndPassword: {
    enabled: true,
  },

  // Better Auth lit automatiquement BETTER_AUTH_SECRET et BETTER_AUTH_URL
  // depuis les variables d'environnement Next.js
})
```

**Créer middleware.ts** (à la racine du projet, au même niveau que package.json) :

```typescript
/**
 * Middleware Next.js — Protection des routes de l'admin.
 *
 * Ce middleware s'exécute AVANT chaque requête vers les routes /admin/*.
 * Il vérifie si l'artiste a une session valide (cookie signé par Better Auth).
 *
 * Si la session est absente ou expirée → redirection vers /admin/login.
 * Si la session est valide → la requête passe normalement.
 *
 * POURQUOI un middleware et pas une vérification dans chaque page ?
 * Un middleware s'exécute côté serveur avant le rendu — impossible à contourner
 * côté client. Une vérification dans une page Server Component peut être oubliée.
 * [D-06] : toute route sous /admin/* redirige si non connecté
 */

import { NextRequest, NextResponse } from 'next/server'
import { auth } from '@/lib/auth'

export async function middleware(request: NextRequest) {
  // Vérifier si l'artiste a une session valide
  const session = await auth.api.getSession({
    headers: request.headers,
  })

  const { pathname } = request.nextUrl

  // Si l'artiste est connecté et tente d'aller sur /admin/login,
  // le rediriger directement vers le tableau de bord
  if (session && pathname === '/admin/login') {
    return NextResponse.redirect(new URL('/admin', request.url))
  }

  // Si l'artiste n'est pas connecté et tente d'accéder à une route protégée,
  // le rediriger vers la page de connexion
  if (!session && pathname.startsWith('/admin') && pathname !== '/admin/login') {
    return NextResponse.redirect(new URL('/admin/login', request.url))
  }

  // Sinon, laisser passer la requête normalement
  return NextResponse.next()
}

export const config = {
  // Ce middleware ne s'applique qu'aux routes /admin/*
  // Les routes publiques (/api/auth, /gallery, etc.) ne sont pas interceptées
  matcher: ['/admin/:path*'],
}
```

**Créer src/app/admin/login/page.tsx** (formulaire de connexion) :

```typescript
/**
 * Page de connexion de l'artiste — /admin/login.
 *
 * Formulaire email + mot de passe connecté à Better Auth.
 * Le Client Component est nécessaire ici pour gérer les événements
 * du formulaire (onChange, onSubmit) et afficher les erreurs.
 *
 * POURQUOI 'use client' ?
 * Les formulaires interactifs avec état (chargement, erreurs) nécessitent
 * React côté client. Le reste de l'admin peut rester Server Component.
 *
 * [D-04] : admin accessible à /admin
 * [D-05] : email + mot de passe uniquement
 */

'use client'

import { useState } from 'react'
import { useRouter } from 'next/navigation'

export default function AdminLoginPage() {
  const router = useRouter()

  // État du formulaire : champs, chargement, erreur
  const [email, setEmail] = useState('')
  const [password, setPassword] = useState('')
  const [loading, setLoading] = useState(false)
  const [error, setError] = useState<string | null>(null)

  /**
   * Soumission du formulaire de connexion.
   *
   * Appelle l'endpoint Better Auth /api/auth/sign-in/email.
   * En cas de succès, Better Auth pose un cookie de session httpOnly
   * et on redirige l'artiste vers le tableau de bord.
   */
  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault()
    setLoading(true)
    setError(null)

    try {
      const response = await fetch('/api/auth/sign-in/email', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ email, password }),
      })

      if (!response.ok) {
        // Better Auth retourne un message d'erreur dans le corps JSON
        const data = await response.json() as { message?: string }
        setError(data.message ?? 'Email ou mot de passe incorrect')
        return
      }

      // Connexion réussie — rediriger vers le tableau de bord
      router.push('/admin')
    } catch {
      setError('Erreur de connexion. Vérifiez votre réseau.')
    } finally {
      setLoading(false)
    }
  }

  return (
    <main style={{
      display: 'flex',
      justifyContent: 'center',
      alignItems: 'center',
      minHeight: '100vh',
      fontFamily: 'sans-serif',
    }}>
      <div style={{ width: '100%', maxWidth: '400px', padding: '2rem' }}>
        <h1 style={{ marginBottom: '1.5rem' }}>Galerie POF — Administration</h1>

        <form onSubmit={handleSubmit}>
          {/* Champ email */}
          <div style={{ marginBottom: '1rem' }}>
            <label htmlFor="email" style={{ display: 'block', marginBottom: '0.25rem' }}>
              Email
            </label>
            <input
              id="email"
              type="email"
              value={email}
              onChange={(e) => setEmail(e.target.value)}
              required
              disabled={loading}
              style={{ width: '100%', padding: '0.5rem', fontSize: '1rem', boxSizing: 'border-box' }}
              placeholder="artiste@exemple.com"
            />
          </div>

          {/* Champ mot de passe */}
          <div style={{ marginBottom: '1.5rem' }}>
            <label htmlFor="password" style={{ display: 'block', marginBottom: '0.25rem' }}>
              Mot de passe
            </label>
            <input
              id="password"
              type="password"
              value={password}
              onChange={(e) => setPassword(e.target.value)}
              required
              disabled={loading}
              style={{ width: '100%', padding: '0.5rem', fontSize: '1rem', boxSizing: 'border-box' }}
            />
          </div>

          {/* Message d'erreur — affiché si la connexion échoue */}
          {error && (
            <p style={{ color: '#c00', marginBottom: '1rem' }}>{error}</p>
          )}

          <button
            type="submit"
            disabled={loading}
            style={{
              width: '100%',
              padding: '0.75rem',
              fontSize: '1rem',
              cursor: loading ? 'not-allowed' : 'pointer',
              backgroundColor: '#111',
              color: '#fff',
              border: 'none',
            }}
          >
            {loading ? 'Connexion en cours…' : 'Se connecter'}
          </button>
        </form>
      </div>
    </main>
  )
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /api/auth/* | Requêtes de connexion et déconnexion — données non fiables |
| middleware.ts → Cookie session | Le cookie est lu depuis les en-têtes HTTP — vérification cryptographique obligatoire |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-01 | Spoofing | Cookie de session | mitigate | Better Auth signe les cookies avec BETTER_AUTH_SECRET (HMAC) — vérification automatique à chaque requête dans auth.api.getSession() |
| T-01-03-02 | Tampering | POST /api/auth/sign-in/email | mitigate | Validation Better Auth : email format vérifié, mot de passe hashé bcrypt, pas de données raw en DB |
| T-01-03-03 | Repudiation | Tentatives de connexion | accept | Usage personnel artiste seul — log d'audit non requis pour ce volume |
| T-01-03-04 | Information Disclosure | Messages d'erreur login | mitigate | Better Auth retourne "Invalid credentials" générique — pas de distinction "email inconnu" vs "mauvais mot de passe" (évite l'énumération de comptes) |
| T-01-03-05 | Denial of Service | Bruteforce /api/auth/sign-in | accept | Usage personnel artiste seul — rate limiting Better Auth intégré à activer en Phase 6 (prod) |
| T-01-03-06 | Elevation of Privilege | Contournement middleware | mitigate | Vérification de session dans chaque Server Component /admin en plus du middleware (défense en profondeur) |
