**2. Créer `src/components/layout/ModalTrigger.tsx`**

```typescript
'use client'
/**
 * Client Component qui détecte le paramètre URL ?identify=1 et ouvre VisitorProfileModal.
 *
 * POURQUOI un composant séparé ?
 * useSearchParams() est un hook React — impossible dans un Server Component.
 * SiteNav est maintenant un async Server Component (D-15) — il ne peut pas
 * appeler des hooks. Ce composant est le seul pont entre le param URL et l'état modal.
 *
 * PIÈGE CRITIQUE Suspense : useSearchParams() exige un <Suspense> parent.
 * Sans Suspense, `next build` échoue avec "Missing Suspense boundary with useSearchParams".
 * Toujours utiliser : <Suspense fallback={null}><ModalTrigger /></Suspense>
 * [VERIFIED: src/app/page.tsx lignes 19-22 — commentaire PIÈGE 2]
 *
 * POURQUOI router.replace() dans handleClose ?
 * Nettoie ?identify=1 de l'URL sans rechargement de page (history.pushState compatible).
 * Évite que le modal se ré-ouvre si l'utilisateur fait retour navigateur.
 */
import { useSearchParams, useRouter } from 'next/navigation'
import { useEffect, useState } from 'react'
import { VisitorProfileModal } from '@/components/visitor/VisitorProfileModal'

export function ModalTrigger() {
  const searchParams = useSearchParams()
  const router = useRouter()
  const [isOpen, setIsOpen] = useState(false)

  // Ouvrir le modal si ?identify=1 est dans l'URL
  useEffect(() => {
    if (searchParams.get('identify') === '1') {
      setIsOpen(true)
    }
  }, [searchParams])

  function handleClose() {
    setIsOpen(false)
    // Nettoyer le paramètre URL sans rechargement de page
    router.replace(window.location.pathname)
  }

  return <VisitorProfileModal isOpen={isOpen} onClose={handleClose} />
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SiteNav → iron-session | Session visiteur lue depuis cookie — lecture uniquement, jamais d'écriture |
| ?identify=1 → ModalTrigger | Paramètre URL contrôlable par l'utilisateur — doit uniquement déclencher l'ouverture du modal, pas d'action sensible |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Information Disclosure | SiteNav — displayName dans le rendu HTML | accept | displayName est une donnée non-sensible choisie par le visiteur lui-même (pseudo public). Seul le premier caractère est affiché. |
| T-05-05-02 | Spoofing | SiteNav — session.visitorId forgeable ? | mitigate | iron-session utilise AES-256-CBC pour signer le cookie — non forgeable sans la clé secrète `SESSION_SECRET`. SiteNav lit uniquement — pas de mutation possible ici. |
| T-05-05-03 | Tampering | ?identify=1 injecté dans l'URL | accept | Le paramètre URL déclenche uniquement l'ouverture d'un modal côté client — aucune mutation DB, aucun accès aux données. Risque nul. |
| T-05-05-04 | XSS | displayName dans le span initiale | mitigate | `{session.displayName?.[0]?.toUpperCase()}` est un string scalaire rendu dans JSX — React échappe automatiquement les caractères HTML dangereux. Pas de dangerouslySetInnerHTML. |
| T-05-05-05 | Denial of Service | next build échoue si Suspense manquant | mitigate | ModalTrigger toujours enveloppé dans `<Suspense fallback={null}>` dans layout.tsx — documenté dans les commentaires (D-17, Pitfall 4) |
</threat_model>
